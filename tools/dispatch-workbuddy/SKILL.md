# 分发给 WorkBuddy（交接文档）

## 什么算「完成」

把**之前对话里有效的部分总结成一份交接文档**，确保用户拿得到（文件已写出 + 路径已告知 / 已尝试打开）→ **分发任务就算完成**。

- 第一轮：**用户手动**把该文档（内容/图片）交给 WorkBuddy。
- 不要在小窗里继续硬啃同一难题，也不要谎称 WB 已经开好会话。
- 自动投递给 WB 属第二期，本技能不做。

## 标准步骤

1. **调用工具** `dispatch_task`：
   - `target`: `workbuddy`
   - `reason`: 为何分发（上下文不够 / 长工程 / 多文件重构…）
   - `title` / `summary` 可省略：系统会按会话标题与有效消息自动压缩
2. 系统会自动：
   - 从**当前会话**提取有效消息（用户/助手正文，不含工具噪声）
   - 复制会话中的图片到交接目录
   - 写 Markdown 交接
   - 尝试用系统默认程序**打开该文件**
3. 把工具返回的 **完整文件路径** 原样告诉用户。
4. 用一两句话说明用法：打开的文档里有「任务摘要 + 有效消息 + 图片」，第一轮请粘贴/交给 WorkBuddy 继续。

## 工具不可用时的退化

用 `write_file` 自写交接，路径：

`agent-data/dispatch/workbuddy/<可识别标题>.md`

文档结构：

```markdown
# 交接：<标题>

- 目标：WorkBuddy
- 来源：float-agent
- 原因：<为何分发>
- 投递：第一轮请用户手动交给 WB

## 任务摘要
<要 WB 做什么>

## 有效消息
<按时间列出用户/助手关键正文，已截断过长内容>

## 图片
- `agent-data/images/...`（若无则写「无」）

## 怎么用
把本文内容交给 WorkBuddy 新会话继续。
```

写完后告诉用户路径；能用命令打开文件时再打开（Windows：`explorer.exe <文件路径>`）。

## 不要做

- 不要去设置页配置 drop 目录/权限（产品不走那条 UI）。
- 不要调用不存在的 WB CLI/远程 API 做「自动投递」。
- 分发完成 ≠ 再写一条长期记忆；若还要「做过什么/错因」，另走 `remember`（做完后提议记忆），并等用户审批。
- 不要把工具执行细节、半截报错原样塞进交接正文——只保留对 WB 有用的结论与约束。

- [ ] `dispatch_task` 已调用（或已写出退化 md）

- [ ] 已说明「第一轮手动交给 WB」
